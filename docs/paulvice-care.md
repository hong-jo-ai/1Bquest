# PAULVICE CARE — 구매자 케어 등록

작성 2026-08-29 · 상태: 기획 초안

---

## 1. 왜 하는가

폴바이스 발송 고객 1,042명 중 **698명(69%)이 마켓 경유**다. 무신사·W컨셉·29CM·공동구매·카카오선물에서
산 사람들인데, 이들의 연락처는 **배송 목적으로만** 받은 것이라 광고 문자를 보낼 수 없다(정보통신망법).
마켓 계약상으로도 금지다.

그래서 이 698명에게 닿는 **합법적인 경로는 상품에 동봉하는 인쇄물 하나뿐**이다.
PAULVICE CARE 는 그 카드 한 장을 "고객이 스스로 우리에게 걸어오게 만드는 장치"로 쓴다.

**돈으로 보면**: 에끌라 오벌 기준 개당 남는 돈이 자사몰 60,404원 / 마켓 41,342원 —
**한 사람을 자사몰로 옮길 때마다 19,000원**이 더 남는다. 재구매율이 현재 8.2%뿐이라
옮겨온 고객이 한 번만 더 사도 회수된다.

## 2. 이름과 정의

| 쓸 말 | 쓰지 말 말 | 이유 |
|---|---|---|
| **PAULVICE CARE** | — | 프로그램명 |
| **구매자 케어 등록** | 정품 등록 | 시리얼·정품 판정을 하지 않는다. 고객이 증빙을 찾게 만들면 거기서 이탈한다 |
| **제품 선택** | 시리얼 입력 | "내가 산 제품을 골랐다"는 감각이면 충분 |
| **광고성 정보 수신 동의** | 혜택 알림 / 소식 받기 | 법정 용어를 그대로 써야 동의가 유효하다 |

시리얼 넘버를 새로 만들지 않는다. 등록의 목적은 진위 판정이 아니라 **관계의 시작**이다.

## 3. 전체 흐름

```
외부몰 구매 → 케이스 오픈 → CARE 카드 → QR 스캔 → 30초 등록 → 스트랩 할인 → 자사몰 첫구매
```

각 단계에서 이탈이 나므로, 설계 원칙은 하나다 — **단계마다 요구하는 것을 최소로.**

## 4. 혜택 — 딱 세 개

| 혜택 | 고객이 보는 문구 | 실제 운영 | 우리 원가 |
|---|---|---|---|
| ① **배터리 교체 1회 무료** | "배터리 교체 1회 무료" | 요청 시점에 *작업은 무료, 반송 택배비만 부담* 안내 | 교체 단가 **2,200원** (파쇼 P26-006 실적) |
| ② **PAULVICE CARE 간편 A/S** | "간편 A/S" | 등록 고객은 접수 시 구매정보 조회 불필요 — 바로 접수 | 기존 AS 체계 그대로 |
| ③ **스트랩 구매 할인** | 완료 화면에서 쿠폰 즉시 제시 | 자사몰 전용 쿠폰 | 스트랩 원가 3,100~5,470원 / 판매가 25,000원 |

**배터리 조건(택배비 부담)은 등록 단계에서 강조하지 않는다.** 카드와 랜딩에서는 "1회 무료"만 말하고,
실제 요청이 들어온 시점에 안내한다. 등록 화면에 조건을 나열하면 그 자리에서 이탈한다.
단, **약관 페이지에는 명시**한다(고지 자체를 빼면 나중에 분쟁이 된다).

## 5. CARE 카드 — 전단이 아니라 언박싱의 첫 장면

### 배치
시계 케이스 뚜껑을 열었을 때, **시계를 보기 전에 반드시 들어올려야 하는 위치**.
카드를 치우는 동작이 곧 카드를 읽는 동작이 된다.

### 담기는 것
- **"배터리 교체 1회 무료"** — 가장 큰 글자
- **QR 코드** — 크게
- 그 외 설명은 최대한 덜어낸다

### 담지 않는 것
혜택 3종 나열 · 약관 · 브랜드 스토리 · 상세 안내 — 전부 랜딩으로 넘긴다.
카드의 목적은 **정보 전달이 아니라 QR 스캔 유도** 하나다.

### 색
BI 팔레트 안에서 **가장 대비 강한 조합** = **먹지 #111 바탕 + 백색 #fff 글자.**
행동 유도용으로만 쓰고, 그라데이션·골드 액센트는 금지(BI 위반).
서체는 Pretendard, 세리프는 워드마크에만.

> ⚠️ BI 확인 필요: 폴바이스 사진·영상은 밝은 자연 컬러가 기본이지만 **그래픽·타이포는 모노톤**이
> 규칙이라 먹지 카드는 BI 안쪽이다. 그래도 실물 인쇄 전 대표 확인 1회.

## 6. 랜딩 페이지 — 30초 안에 끝나야 한다

### 화면 1 — 진입 (QR 스캔 직후)
```
PAULVICE CARE
구매하신 PAULVICE를 등록하세요
배터리 교체 1회 무료
[ 등록 시작 ]
```
설명 문단 없음. 스크롤 없이 한 화면.

### 화면 2 — 본인 확인
휴대폰 번호 입력 → **문자 인증번호 6자리**.

> 구현 메모: PASS/NICE 본인인증은 계약·건당 수십원이 든다. 우리는 이미 Solapi 를 쓰고 있으므로
> **SMS OTP** 로 충분하다(건당 수 원). 이름·주민번호를 받지 않으니 개인정보 최소수집 원칙에도 맞다.

### 화면 3 — 제품 선택
구매한 제품을 **이미지 그리드에서 하나 탭**. 시리얼·주문번호·구매처 입력 없음.
목록은 판매 중인 시계 전 모델 + "목록에 없어요" 하나.

### 화면 4 — 동의 (분리해서 받는다)
```
[필수] PAULVICE 케어 서비스 제공을 위한 개인정보 수집·이용 동의
        수집항목: 휴대폰번호, 등록 제품
        이용목적: 케어 서비스(배터리 교체·A/S) 제공
        보유기간: 서비스 종료 또는 동의 철회 시까지

[선택] 광고성 정보 수신 동의 (문자)
        미동의해도 케어 서비스는 그대로 제공됩니다
```
**필수·선택을 시각적으로 분리**하고, 선택 항목은 기본 체크 해제. "혜택 알림" 같은 완곡어 금지.

### 화면 5 — 완료 + 쿠폰
```
등록 완료
배터리 교체 1회 무료가 적용되었습니다

스트랩 할인 쿠폰이 발급되었습니다
[ 스트랩 보러가기 ]
```
쿠폰은 **화면에서 바로 제시**하고 자사몰 상품으로 연결. 문자로 다시 보내주는 건 부차적이다
(그 자리에서 안 사면 대부분 안 산다).

## 7. 개인정보 — 두 동의를 섞지 않는다

| | 필수 동의 | 선택 동의 |
|---|---|---|
| 근거 | 개인정보보호법 §15 (계약 이행) | 정보통신망법 §50 (광고성 정보) |
| 없으면 | 케어 서비스 제공 불가 | 광고 문자 발송 불가 (서비스는 정상 제공) |
| 수집 | 휴대폰번호, 등록 제품 | 동일 |

**선택 동의를 받아두면 6개월 제한이 사라진다.** 현재 자사몰 직접구매자에게는 "거래관계 6개월 이내
동종상품" 예외로 광고를 보낼 수 있지만, 마켓 구매자는 그 예외가 적용되지 않는다(직접 수집이 아님).
CARE 등록에서 받은 동의가 **마켓 고객에게 합법적으로 연락할 수 있는 유일한 열쇠**다.

발송 시 준수: `(광고)` 표기 · 무료 수신거부 방법 · 야간(21~08시) 발송 금지.

## 8. 데이터

등록 1건 = 우리 자산 1건.

| 필드 | 용도 |
|---|---|
| 휴대폰번호 | 식별자 겸 발송 채널 |
| 등록 제품 | 재구매 제안의 근거(밴드 러그폭이 모델마다 다르다) |
| 등록일 | 배터리 무료 1회 사용 여부 추적 |
| 광고 수신동의 | 발송 가능 여부 |
| 유입 경로 | 어느 마켓 상자에서 왔는지 — 카드 QR 에 파라미터로 구분 가능 |

기존 `crm_campaign_targets` 와 별개 테이블(`care_registrations`)로 두고,
CRM 캠페인 대상 산출 시 소스 하나로 편입한다.

## 9. 성과 측정

| 지표 | 정의 | 초기 목표 |
|---|---|---|
| 등록률 | 등록 수 ÷ 카드 동봉 수 | 10% |
| 동의율 | 광고 수신동의 ÷ 등록 | 60% |
| 쿠폰 사용률 | 스트랩 구매 ÷ 등록 | 15% |
| **첫 자사몰 구매 전환** | 등록 후 90일 내 자사몰 구매 | 20% |

월 발송이 약 90건(마켓 경유)이니 **등록률 10%면 월 9명**. 작아 보이지만 누적이고,
한 명당 자사몰 이관 가치가 19,000원 + 재구매 가능성이다.

## 10. 운영

- **배터리 교체 요청**: 등록 조회 → 1회 사용 여부 확인 → 회수 안내(반송 택배비 고객 부담) →
  작업 후 발송. 시계는 AS센터(김종근), 주얼리는 나비스트.
- **간편 A/S**: 등록 고객은 구매처·구매일 확인 절차를 생략한다. 실제로 줄어드는 건 CS 왕복 1~2회.
- **쿠폰 소진 관리**: 스트랩 재고와 연동(브라운 340개, 14mm 97개).

## 11. 리스크

| 리스크 | 판단 |
|---|---|
| 구매 증빙 없이 등록 → 안 산 사람이 등록 | 배터리 원가 2,200원이라 감수 가능. 증빙 요구가 이탈을 더 키운다 |
| 마켓이 "고객 빼가기"로 볼 가능성 | 카드는 **상품 동봉물**이고 혜택 제공이 목적. 타 채널 유도 문구를 카드에 넣지 않는다 |
| 배터리 무료 남용 | 1회 한정 + 등록 시점 기록으로 통제 |
| 카드 인쇄비 | 장당 약 200원 — 등록 1건당 획득비용 2,000원 수준(등록률 10% 가정) |

## 12. 구현 단계

1. **랜딩 페이지** (`/care`) — 5화면, SMS OTP, 제품 선택, 동의 분리, 쿠폰 발급
2. **`care_registrations` 테이블** + 등록 API
3. **쿠폰 발급 연동** — 카페24 쿠폰 API
4. **카드 시안** — 먹지+백색, QR, 인쇄 규격 확정
5. **CRM 소스 편입** — `buildLeads()` 에 `care` 소스 추가
6. **대시보드** — 등록 추이·동의율·전환율

1~3이 되면 카드를 찍을 수 있다. 4는 인쇄 리드타임(1~2주)이 있으니 병행.
